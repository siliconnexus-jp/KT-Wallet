# KT Wallet 一线体验实施方案

## 目标

在不引入 WalletConnect、DApp、NFT、Swap、质押、原生 CI 和正式发布签名的前提下，把现有多链钱包的基础体验提升到可长期使用的发布质量：

- 任何失败场景都不展示演示余额或演示交易。
- 冷启动立即展示最后一次可信快照，后台刷新不清空旧数据。
- 弱网、缓存、刷新和失败状态对用户可解释。
- 历史记录可离线恢复、分页加载，并与本地 Pending 记录稳定去重。
- 常用资产可以收藏、隐藏零余额，偏好可持久化。
- 关键操作有克制的触感和按压反馈，并具备完整无障碍语义。
- 能用可复现的指标、双端截图和 HTML 报告证明验收结果。

## 任务编排与验收标准

### E1 数据可信度与缓存

- 删除生产资产页的离线演示数据回退。
- 保留最后一次成功的真实余额；没有快照时显示 `--`。
- 首页和资产页显示“刚刚更新 / N 分钟前 / 数据可能已过期”。
- 钱包、网络环境切换时严格隔离缓存。

验收：断开 Gateway 和 RPC 后重新启动，页面只显示同钱包、同网络的真实快照；从未成功加载的资产显示 `--`，不得出现设计稿余额。

### E2 历史记录可靠性

- 为远端历史增加按钱包和网络隔离的持久快照。
- 首屏优先展示快照，再进行后台刷新。
- 支持“加载更多”；每次扩大远端窗口并稳定去重。
- 本地 submitted/pending/confirmed 记录继续优先合并。

验收：成功加载历史后离线重启仍可查看；点击加载更多后记录数增加或明确到达末尾；同一 hash 不重复。

### E3 请求与弱网体验

- Gateway 余额 Token 查询保持有界并发。
- 客户端共享 HTTP 连接与 Gateway 能力探测。
- 对 Gateway 优先路径采用快速失败，再进入直连回退。
- 记录关键刷新阶段耗时，用于测试报告输出。

验收：单一慢链不清空其他链结果；Gateway 不可达时页面保持缓存且可操作；刷新过程没有整页白屏。

### E4 资产管理

- 增加隐藏零余额、收藏资产和持仓排序选项。
- 收藏与筛选按本地偏好持久化。
- 收藏资产优先，其次按持仓价值排序。

验收：重启后偏好仍存在；搜索和网络过滤继续正确。

### E5 交互、无障碍与反馈

- 主要按钮、资产行、交易行增加轻量触感反馈。
- 高频操作只使用 100–160ms 的按压反馈，不增加阻塞动画。
- 收款、转账、记录、资产和设置入口具备明确的 Semantics 标签。
- 加载、错误、空状态和缓存状态可被 VoiceOver/TalkBack 朗读。

验收：开启屏幕阅读器后能完成首页到转账确认的基本路径；减少动态效果设置不影响功能。

### E6 交易确认

- App 回到前台时立即续查 Pending。
- 状态变化为 confirmed/failed 时在 App 内提供一次性通知。
- 后台推送作为服务端 Device Token 注册能力的后续独立任务；本轮不伪装成已支持系统级后台推送。

验收：转账后离开再返回，状态自动更新且不产生重复记录。

### E7 验证和报告

- Flutter 全量测试、静态分析。
- Gateway Go 全量测试和 race test。
- iOS Simulator 与 Android Emulator 分别运行核心路径。
- 截图覆盖：冷启动缓存、刷新状态、离线状态、资产筛选、历史分页、交易确认和安全页面。
- 输出包含环境、步骤、结果、截图和已知限制的 HTML 报告。

## 完成定义

只有当 E1–E7 的代码、测试和双端证据全部存在时，才可宣称本轮体验升级完成。报告必须区分自动化通过、模拟器 UI 通过、真实测试网链上通过和仍需真机/生产验证的项目。
